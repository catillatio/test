# Android release candidate and owner signing

This directory reconciles historical draft PR #20 with the current production UI. It does not merge the old backend branch. No new runtime framework, native game state, analytics, billing or push dependency is added.

## Build contract

- Java/platform Activity + WebView; AGP 8.13.2, checksum-pinned Gradle 8.13, Java 17 source, compile/target API 36, build tools 36.0.0, minimum API 26.
- Preview application ID `game.kingdomcome.alpha`; debug suffix `.debug`; candidate versionName `0.2.0-beta.1`, versionCode `2`. **The preview ID is not an owner-selected permanent Play identity.** Never upload under it by accident. The signing helper refuses that ID.
- Owner selects permanent reverse-domain ID once, before first upload. Pass `-PkingdomApplicationId=...`; keep it stable for all updates. Each upload needs an unused, larger positive integer `kingdomVersionCode`; the current validation permits 1–999,999,999, below Play's 2.1-billion limit. VersionName is a user-facing semantic label. Server/UI deployments do not alone require reinstalling the WebView client.
- `./gradlew --no-daemon testDebugUnitTest testReleaseUnitTest lintDebug lintRelease assembleDebug assembleDebugAndroidTest bundleRelease` creates debug APK/test APK and **unsigned** release AAB. Unsigned AABs are not installable or uploadable release artifacts.
- PR workflow `android-alpha.yml` builds/verifies those exact-head artifacts and runs two real-emulator platform/WebView smoke jobs (API 29/36). No production URL is contacted: instrumentation starts only a debug-only fixture Activity and intercepts every request. It reuses actual `WebViewSecurity.configure`. These limited smoke tests do not certify real-device gameplay, keyboard/cutout/gesture behavior or production login.

## Protected signing setup — owner only

Do not paste credentials in chat, repository files, PRs or workflow inputs. No release key is generated by Codex. Use the owner's approved upload keystore and keep an offline recovery copy. Google Play App Signing can hold the distinct app-signing key; an upload key is not automatically the installed app certificate.

After an authorized merge, owner creates/configures the GitHub environment `android-release`, restricting it to `release/production` and requiring the normal owner review. Add:

| Kind | Name | Content |
|---|---|---|
| Variable | ANDROID_APPLICATION_ID | Final owner-selected permanent application ID |
| Variable | ANDROID_UPLOAD_CERT_SHA256 | Public upload-certificate SHA-256, 64 hexadecimal digits |
| Secret | ANDROID_UPLOAD_KEYSTORE_BASE64 | Base64 of existing upload keystore; never a game/retention key |
| Secret | ANDROID_STORE_PASSWORD | Existing keystore password |
| Secret | ANDROID_KEY_PASSWORD | Existing alias password |
| Secret | ANDROID_KEY_ALIAS | Existing alias |

The separate **Kingdom Come signed Android bundle** workflow is manual, release-branch only and protected by that environment. It first requires green complete exact-head production push CI and unchanged branch identity, and builds/tests/lints before reading signing material. `scripts/sign-release.py` writes a 0600 temporary key file, passes passwords through process environment rather than arguments, captures private tool errors, signs once and requires the expected **public** certificate fingerprint. It removes the temporary directory and uploads only AAB/checksum/public verification report. It never submits to Google Play or invokes Railway. Failed or uncertain signing must be inspected; do not assume an artifact is uploadable.

Owner dispatches with the next approved versionCode/versionName, verifies `OWNER_UPLOAD_SIGNED`, exact source commit, application ID and public certificate in `bundle-verification.json`, then enrolls in Play App Signing and uploads manually to an internal/closed track. The app-signing certificate shown by Play may differ from the upload certificate. Preserve both for update verification. Do not change package IDs or keys to “fix” an update failure.

## Artifact verification

`verify-bundle.py` requires checksum-pinned official bundletool 1.18.3, validates the real bundle and decoded compiled manifest, target/min SDK, sole INTERNET permission, non-debuggable/non-test release, backup/cleartext restrictions, exported-component count, no native libraries, no fixture Activity, no key/dump files and JAR signature/public certificate when signing is required. No native `.so` files means no application-native 16-KB alignment payload; the OS-provided WebView is maintained separately. This is not physical 16-KB-device evidence.

Debug APKs use disposable debug certificates and the separate `.debug` package, preserving release identity. They do not update historical PR20 alpha installs in place; never tell a player to uninstall production to test an unsigned preview. The signed AAB's update compatibility remains unverified until the owner confirms the permanent identity/certificate and a Play-distributed upgrade is tested.

## Manual device acceptance

Test a real recent Galaxy S device, midrange Galaxy A, Pixel and budget Android. Record Android and System WebView versions, navigation mode, font size, logical viewport and client version. Check login/logout/session persistence; five tabs and Android Back; predictive gesture/system bars/cutouts; IME focus and submit; 200% text; rotation/split screen; background/foreground and renderer/network failure; no POST resubmission after interruption; sound after gesture; TalkBack labels/focus; every purchase/Vault/battle command's saved receipt. Use authorized synthetic accounts on an isolated realm, not production player accounts. Review Play pre-launch report separately. Browser matrices are not Samsung performance measurements.

SDK setup explicitly disables automatic license acceptance. Emulator installation uses existing runner SDK licenses and closed stdin. No `yes | sdkmanager --licenses` fallback is allowed; missing acceptance is an owner/platform blocker.

Emulator evidence: the first API29 run stalled in ADB installation after successful boot, before instrumentation. The harness now uses documented `adb install --no-streaming` (and `-t` for the instrumentation APK), with 90-second install, 120-second instrumentation and 15-second cleanup bounds. It never retries or counts a cancelled/timed-out test as passed. See [ADB command reference](https://android.googlesource.com/platform/packages/modules/adb/+/HEAD/docs/user/adb.1.md).
