# Kingdom Come — Android release candidate

Permanent application ID and Java namespace: **game.kingdomcome.rpg**. Public name:
**Kingdom Come**. Actual Play Console registration/availability is owner-confirmed;
public search is not proof. Gradle, the release manifest verifier and protected
signer reject any other permanent ID. Debug uses `game.kingdomcome.rpg.debug` and
cannot overwrite the release app. No unrelated ID is substituted.

## Verified build path

Current min SDK 26 / compile SDK 36 / target SDK 36; API 36 satisfies the published Google
Play August 31, 2026 new-app/update requirement. VersionCode 2 / versionName 0.2.0-beta.1
are the candidate defaults; the owner must use a code higher than any existing Play
upload. The Gradle override validates positive codes and semantic release labels.

Ordinary Android readiness CI runs unit tests/lint, compiles release AAB and debug
app/test APKs, then uses the checksum-pinned official bundletool to validate the real
compiled AAB manifest. Artifact `kingdom-come-android-alpha-<run>` is a legacy label,
not an alternate application ID. `bundle-verification.json` binds exact source SHA,
package, version, bytes, SHA256, SDKs, INTERNET-only permissions and signing status.
The unsigned artifact is named **kingdom-come-UNSIGNED-NOT-UPLOADABLE.aab**. It is not
a Play-ready binary and must never be submitted. No private upload key enters PR CI.

The verifier rejects debuggable/test release builds, cleartext/backup access, extra
exported components, native libraries, test-only Activities and key/dump artifacts.
No application-native `.so` files are present, so there is no application-native
16KB page-alignment payload to repair; this does not certify physical-device behavior.

## Compatibility and evidence limits

Actual API 29/API 36 emulator instrumentation exercises the production WebView
security configuration with an intercepted synthetic fixture, no production
requests. It covers trusted HTTPS navigation, blocked external resources, Back,
state restoration and safe recovery. Failed/time-limited installation is never
retried or accepted blindly: independent exact installed-pair bytes/instrumentation
verification is required before every remaining smoke assertion. Existing bounds,
SDK license safeguards and assertions remain unchanged. No Windows execution needed.

The real Fastify/EJS browser matrix covers 360/384/393/412 CSS pixels alongside 320,
390,432,600,800 and1280, all player-facing test scenes, tablet layouts and genuine
1080×1920 gameplay captures. Browser measurements are not Android-device certification.
Existing native insets/IME/rotation, HTTPS/session/CSRF and server-authoritative
transactions are preserved. No native JS bridge, file/content/mixed-content loads,
third-party cookies, debug WebView or POST replay fallback is enabled.

Physical Galaxy/Pixel/budget-device testing, TalkBack and Play pre-launch reports
remain useful engineering acceptance recommendations, not an invented universal
third-party certification requirement before internal testing. Examine actual
Console/pre-launch findings and fix concrete failures. Google may impose additional
account-specific testing/device-verification requirements in Console.

A signed package is insufficient while privacy/deletion endpoints or fulfillment
are not live. See the Play readiness report for separate owner deployment, legal
text, retention and erasure-operation approvals. None is activated automatically.
